# Vision, training, and gaze

The vision developer owns the two laptop pipelines fed by one webcam. Confusion inference emits an interval when the face signal suggests the user may want help. Gaze estimation emits positions and uncertainty for that display. The desktop developer can integrate both outputs using replay before a trained model is available. [Shared protocol](protocol.md)

## Data and evaluation

| Source | What to use | Limits |
| --- | --- | --- |
| DAiSEE | Use the official person-disjoint split. Run an initial clip-level experiment against the test-set majority class. Most recordings have bust framing from a mounted 1080p/30 fps webcam. | The 9,068 released clips come from 112 Asian students aged 18–30, including 32 women and 80 men. Ten-second ratings describe observer judgments. The paper reports 72.3% four-level confusion accuracy for its temporal baseline and 57.45% for a face-cropped CNN. | OL-SFED | Use as a secondary learning-domain check after verifying access and permitted use. Its 267 confusion clips include variation in glasses and occlusion across 82 participants. | The samples are selected short expressions. Use them for recognition, then measure interval boundaries against the first-party sessions. [Dataset paper](https://ietresearch.onlinelibrary.wiley.com/doi/10.1049/iet-cvi.2018.5281) |

Record adults debugging software and following tutorials. After each task, ask them to mark when they got stuck, first wanted help, and recovered. Record instances where concentration, reading, surprise, or frustration led to no request for help. Track participant, task, camera, resolution, lighting, and glasses or occlusion in the experiment manifest. Use the help-wanted through recovery range for operational positives and retain the stuck time for analysis. Exclude uncertain boundaries from supervision and document how much data was excluded.

Split by participant before deriving windows or augmentations. Keep a final set of unseen people and report debugging and learning separately, with per-participant counts and coverage. Use public clip labels at clip level. For a binary DAiSEE comparison, document the mapping of levels 2–3 to positive and 0–1 to negative, and pool predictions across each clip. The four-level paper accuracies and the binary results measure different tasks.

## Confusion model

1. Open one camera track at up to 720p/30 fps with audio disabled. The dedicated vision worker receives frames and source timestamps. Sample distinct frames by time. Gaze and confusion each have their own rate and drop stale work when behind. Publish effective rates and dropped-frame counts.
2. Run YuNet at the detector cadence. Pin the ONNX asset, input shape, and license. Letterbox for the detector and map its box and five landmarks back to the camera frame. Select the stable primary face and pause scoring when faces are ambiguous or the tracked person changes. Align using the eye landmarks, crop with a fixed 20% margin per side, and resize to 112 × 112 RGB. Use the same crop, alignment, and channel normalization in training and inference. Measure usable crop coverage across framing, lighting, and occlusion on the target webcams. [YuNet model card](https://huggingface.co/opencv/face_detection_yunet)
3. Remove the MobileNetV3-Small classifier and pool the backbone to 576 features. Project to 128, run a single unidirectional GRU with 128 hidden units, and return a binary softmax score where class index 1 is likely confusion. Train in PyTorch on Vast, outside the demo API service. Use four-second sequence chunks and carry detached recurrent state between consecutive chunks within one track. Reset at track boundaries. Start at 8 Hz and compare 4, 8, and 16 Hz against a pooled CNN without recurrence. Compare event performance and laptop load with screen recording active. [Torchvision architecture](https://github.com/pytorch/vision/blob/main/torchvision/models/mobilenetv3.py)
4. Export a one-frame ONNX graph with normalized `frame_rgb: float32[1,3,112,112]` and `state_in: float32[1,1,128]`. Return `probabilities: float32[1,2]` and `state_out: float32[1,1,128]`. Regression-check the exported model against PyTorch using sequential frames and a reset. Ship the model version, asset checksum, normalization, and default cadence with the model artifact. Use ONNX Runtime in the local vision worker and start with CPU execution. The architecture estimate is 1.1M parameters and 4.4 MB of FP32 weights before runtime assets. [ONNX Runtime JavaScript](https://onnxruntime.ai/docs/get-started/with-javascript/)

Treat pupil dilation and facial color as separate experiments on original-resolution regions with controlled changes in lighting and exposure. Keep those features out of the baseline so improvement can be attributed to them and measured across people and devices. [Pupil light-reflex study](https://pubmed.ncbi.nlm.nih.gov/24110409/) · [Webcam facial-color measurement study](https://www.nature.com/articles/s41746-021-00462-z)

## Interval state machine

- Warm up for four seconds of usable history. Smooth the confusion score with a time-based exponential average, initially with a 350 ms time constant. A score of at least 0.70 for one second starts an interval at the first qualifying sample.
- A score of 0.40 or below for one second ends the interval at the start of that low-score run. If the interval is still active at eight seconds, finalize at the eight-second boundary. Keep the peak score and the first and last contributing frame IDs, then emit one finalized event.
- Rearm when the score has stayed at or below 0.40 for one second and at least 15 seconds have elapsed since publishing. A missing face, ambiguous track, or low-quality frame enters an unknown state. Break pending threshold runs on invalid samples. If lost for 500 ms, or if the camera or timeline restarts, clear pending state and recurrent memory and warm up again. Keep any existing cooldown. Use the quality marker and abstention rate when evaluating performance.
- Match predictions one-to-one to held-out help-wanted intervals, with at least 0.30 temporal intersection over union. Report interval precision and recall, false panes per hour, onset and publish delays, usable-face coverage, and dropped frames. Initial wider-use targets are at least 80% precision, at least 60% recall, and at most one false pane per 15 minutes. These are targets for evaluation. Use live detection in the staged demo when it is dependable, with replay and manual help available.

## Gaze calibration and export

Run MediaPipe Face Landmarker locally in the vision worker at a target of 20 Hz from the same camera. Bundle the WASM and model assets after checking their redistribution terms. Turn on facial transformation matrices for head pose. Use the relative center of each iris within its eye, yaw, pitch, and roll as regression inputs. Treat face presence and tracking thresholds as input-quality checks. A WebGazer study measured 12 Hz in the lab and 26 Hz on the web. Use that variability to inform testing across laptops, and measure MediaPipe's own throughput with recording active. [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker) · [Webcam gaze comparison](https://pmc.ncbi.nlm.nih.gov/articles/PMC11627531/)

1. Show nine targets on the selected display. At each, wait 250 ms for the user to settle, then aggregate 500 ms of valid frames. Fit regularized x and y predictors to normalized target coordinates. Validate using five separate target positions. Use the 80th percentile radial residual in encoded pixels as the initial uncertainty radius. Record median error, coverage, and effective rate. For a starting gate, require a median error within 8% of the viewport diagonal and a usable sample at each validation target.
2. Persist coefficients and error locally under the camera ID and resolution, display ID, scale, orientation, and encoded geometry. Recalibrate when that key changes or the preview shows persistent drift. Use a validity signal for out-of-bounds estimates, blink, excessive pose, or low tracking quality. Preserve the reason internally for diagnostics.
3. Apply a short median filter within each uninterrupted valid run. Interpolate only when valid bracketing observations are less than 100 ms apart and the gap did not include a blink, explicit tracking loss, or an epoch boundary. Emit an invalid point when the gap cannot be filled. The desktop resamples to 5 Hz for the clip and uses full-viewport pixels. Failed calibration leaves video/audio analysis available.

Hand off the ONNX model contract, model metadata, the interval and gaze event examples, and test traces for score recovery, sustained confusion, camera loss, and invalid gaze. Measure inference and gaze throughput together on both target laptops before choosing whether to lower the camera processing rates.
