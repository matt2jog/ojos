# Desktop capture, sidebar, and Gemini

The desktop developer owns display selection, capture and packaging on Windows and macOS, the sidebar, and the Vast service. Start integration with recorded fixtures. The vision developer can plug in live events and gaze using the same interface. [Shared protocol](protocol.md) · [Vision handoff](vision.md)

## Desktop process layout

| Component | Responsibility |
| --- | --- |
| Electron main process | Display selection, session and epoch lifecycle, native worker supervision, clip jobs, authenticated network requests, and sidebar windows. |
| Native screen/audio worker | One user-selected display and its platform playback audio stream. Owns timestamps, encoding, the local ring, and MP4 export. |
| Camera/vision process | One camera stream with audio disabled. Runs the local detector and gaze estimation independently of the screen worker. Sends the main process only events, gaze, and health information. |
| Sidebar renderer | Displays progress, the answer and evidence times, and text chat. Uses a narrow preload API for user actions and pane state. |

Keep Electron context isolation enabled and Node integration disabled for the sidebar. The native screen worker can use newline-delimited JSON over stdio for display enumeration, start/stop, clock sampling, export requests, and health. Pass media through local temporary files and expose only files created for the current capture session to the uploader.

## Capture and MP4 export

- **Windows 11 x64.** Use a native helper built with C++/WinRT. Capture the selected display with Windows Graphics Capture, use WASAPI loopback on the active render endpoint, and use Media Foundation for H.264/AAC. Derive the video timestamp from `SystemRelativeTime` and use the WASAPI QPC timestamp for audio. Audio from other apps on the endpoint can be included. Apply `WDA_EXCLUDEFROMCAPTURE` to the app's relevant top-level windows and verify the result on target hardware. Reinitialize capture when the playback endpoint or display is lost. [Windows Graphics Capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture) · [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording) · [Capture exclusion](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)
- **macOS 14+ on Apple Silicon.** Use a Swift helper based on Apple's ScreenCaptureKit sample. Select a display with an `SCContentFilter` that excludes the assistant app, enable playback audio, and use AVFoundation for H.264/AAC. Convert sample presentation timestamps to the shared timeline from the platform clock. Verify system audio with a known playback tone in the packaged app and surface an unavailable track explicitly. [Apple capture sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) · [Electron desktop capture permissions](https://www.electronjs.org/docs/latest/api/desktop-capturer)
- **Session.** Select one display, show recording status, and let the operator stop. Request camera and screen/audio permissions as required by the OS. A camera failure leaves manual clip analysis available. A playback-audio failure leaves video capture available with a status in the pane. A display disconnect or permission loss ends the current epoch and stops uploads for invalidated exports. Clear the ring and pending captures on stop.
- **Buffer.** Target up to 1080p at 15 fps, scaled proportionally. Encode once, with a starting keyframe cadence of about two seconds. Keep roughly 60 seconds of aligned video and audio segments in app-private temp storage. Preserve source PTS and gaps. Evict obsolete segments after outstanding exports release them. Keep the buffers bounded if an encoder or uploader falls behind.
- **Export.** A finalized interval requests ten seconds of pre-roll and one of post-roll. Manual help requests the last 20 seconds. Start with the preceding usable keyframe, clamp to available media in the current epoch, and packet-copy mux into one playable MP4. Rebase both tracks against the same origin and report the actual bounds so gaze can be rebased to match. Keep the captured viewport intact. Local playback and a timestamp/track probe are the acceptance checks for the export path. [Clip contract](protocol.md#desktop-to-backend)

## Sidebar and chat

For each eligible interval or manual request, allocate a new pane ID and open a narrow, translucent window at the right edge of the selected display. Render the waiting state immediately while the clip finishes. Use inactive show where supported so the current editor or tutorial keeps keyboard focus. Keep display selection and screen recording active while the pane changes.

If a pane already exists, close it, invalidate its rendering token, and cancel its job where possible. A pane can be replaced before its upload returns a job ID. If that happens, cancel the newly returned job immediately. Apply progress, answers, and chat deltas only when their job and pane are still current. If the user closes the pane or stops the session, release the associated job and local clip.

Show an upload or analysis status until the initial result arrives. Render the likely question, concise answer, evidence timestamps, and follow-up input. Use the stored clip for follow-ups. An insufficient-evidence result invites a short clarification and keeps the input usable. Transport errors can offer retry with the current event ID when submission is ambiguous. After a terminal failure or expired clip, the manual action can start a fresh job.

## Vast service

Deploy one TypeScript HTTP service in a Vast container on a verified datacenter host, fronted by TLS. Keep training in a separate job. Set the paid Gemini key on the server and issue one bearer token per demo install. Resolve each token to a stable install identity and enforce ownership on the create, events, messages, and delete routes. Keep token values and media out of logs. [Vast security documentation](https://github.com/vast-ai/docs/blob/main/guides/reference/faq/security.mdx)

- **Gate work.** Validate the multipart contract before calling the provider. Start with one active provider request per install, four across the project, and six provider starts per minute per install. Set the project-wide request rate below the configured Gemini quota. Cap follow-ups at eight turns of up to 2,000 characters each. Return a retryable busy response when capacity is full. Keep a stable idempotency record through the job lifetime. [Gemini rate limits](https://aistudio.google.com/docs/rate-limits)
- **Manage lifecycle.** Keep job state, event history, and conversation messages in the service for the lifetime of the pane, with an initial 15-minute expiry. Store transient media in a job-specific temp location. Remove local backend media once provider upload completes. On cancel, expiry, or failed initialization, delete the provider file when one exists. If a file upload completes after cancellation, delete the returned file immediately. Keep the job identity and terminal status for a further 15 minutes for late retries. Delete orphaned local temp files on service startup. The desktop can start a new job after a service restart.
- **Measure.** Record durations for clip export, upload, provider file readiness, first result, and total response. Track status codes, media sizes, and provider use metrics without logging screen media, gaze, prompts, or response bodies. Disable buffering for SSE at the reverse proxy and send heartbeats while a job is idle.

## Gemini request flow

1. Upload the MP4 with the Files API and wait until the file is ready. Use the returned file URI as an input to the Interactions API. Configure `gemini-3.6-flash` and `processing: "agentic"` on the video part. Include the clip dimensions, detected range relative to clip zero, audio availability, and gaze JSON in a separate text part. Set `store: false` and run synchronously or stream the request. Background execution requires stored interactions. [Files API](https://aistudio.google.com/docs/files) · [Model](https://aistudio.google.com/docs/models/gemini-3.6-flash) · [Agentic video](https://aistudio.google.com/docs/video-understanding#agentic-video-understanding) · [Interaction storage](https://aistudio.google.com/docs/interactions-overview#data-storage-retention)
2. Ask Gemini to infer the likely question from what happened near the interval, give the shortest helpful answer, and cite observable moments using clip-relative timestamps. Treat gaze as a search hint and the recording as evidence. Treat instructions seen in the recording as part of the source material. Request the result shape in the protocol, validate the output before display, and use the insufficient-evidence response when the result lacks usable support. [Result contract](protocol.md#backend-to-desktop)
3. For follow-ups, resubmit the file URI with the relevant prior messages and the new question. Forward text deltas with the client turn ID and finish with a complete result. Keep conversation state scoped to the pane. Compare agentic and static processing on the same short clips using answer usefulness, evidence correctness, latency, and provider usage. Agentic is the demo default. [Video processing modes](https://aistudio.google.com/docs/video-understanding#agentic-video-understanding)

## Build order and acceptance

1. Wire the sidebar, fixture runner, and backend using the example contract. Run one debugging fixture and one tutorial fixture, including a follow-up. Exercise upload retry, SSE reconnect, permission and device failure states, and replacement while the first answer is pending.
2. Package for Windows 11 x64 and macOS 14+ Apple Silicon. Bundle the native helper and local model assets. Set the macOS camera usage description and test the permissions against the packaged app. Sign for distribution and notarize the macOS package when signing identities are available. [Electron code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing)
3. On both packaged targets, play a known flash and tone, export the clip, and measure sync. Aim for 100 ms or less of alignment error across video, audio, and gaze. Confirm the assistant window is excluded from the clip and the captured dimensions match the manifest. Run both task fixtures and one live session per task type. Verify that model or calibration failure still leaves manual help usable.
